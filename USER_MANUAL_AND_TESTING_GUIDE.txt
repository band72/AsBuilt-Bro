PART 1: SYSTEM OVERVIEW AND ARCHITECTURE
================================================================================

1.1 Executive Summary
--------------------------------------------------------------------------------
Welcome to RCS COGO Enterprise! This application provides state-of-the-art 
Coordinate Geometry (COGO) calculations paired with comprehensive Pipe Network 
modeling and Asset Management capabilities. Built for modern enterprise needs, 
it includes fully scriptable pipelines, an active material database, multi-format 
data exports, AI integration, and a C++ security validation layer.

1.2 System Requirements
--------------------------------------------------------------------------------
- Operating System: Windows 10/11 (64-bit)
- Framework: .NET 8.0 Windows Desktop Runtime
- Database: SQLite (local file-based storage)
- Processor: x64 architecture required for native security DLL
- Memory: Minimum 8GB RAM recommended for large map operations.

1.3 Installation and Deployment
--------------------------------------------------------------------------------
The application is deployed via a single-file executable or an Inno Setup installer. 
Once installed, double click RCS.Cogo.Wpf.exe. Ensure the native 'RcsSecurityModule.dll' 
is preserved in the root executable directory, otherwise the application will fail the 
hardware verification loop.

1.4 Directory Structure
--------------------------------------------------------------------------------
- Views/: WPF XAML UI elements
- ViewModels/: MVVM Logic elements handling state
- Commands/: The specific C# parser implementations for survey geometry
- Entities/: Database models representing EF Core Tables
- Resources/: Shared dictionaries and styles
- DbPath: %LocalAppData%/rcs_installed_assets.db

1.5 Database Architecture (SQLite)
--------------------------------------------------------------------------------
Data is persisted in SQLite using Entity Framework Core.
When dealing with large datasets, ALWAYS utilize the 'Compact Database' menu tool to 
VACUUM the SQLite DB and reclaim filesystem space. Note that figures use heavy Object
Graph hierarchies (Figure -> Vertices -> Point) requiring explicit load state management.

PART 2: USER INTERFACE (UI) REFERENCE
================================================================================

2.1 Main Shell Window Menu
--------------------------------------------------------------------------------
Located at the top of the window, the Main Menu features sections for:
* File -> Exit commands.
* Project -> Load/Save project profiles.
* Settings -> Adjust global rendering tolerances.
* Data -> Access batch scripts, exports, and imports.
* Alignments -> Open standalone managers for H/V alignments.
* Reports -> Generate utility-discipline specific logs.
* Help -> Read this exact manual.

2.2 Points Tab Data Grid
--------------------------------------------------------------------------------
This visual area immediately loads the Points table from the active Project ID.
- Read-only geometry: Northings and Eastings are generated exclusively through commands.
- Writable: Descriptions can be amended inline.
- Highlighting: A checkmark or cross appears if the description aligns with the 'Codes' table.

2.3 Cogo Tab (Command Line)
--------------------------------------------------------------------------------
Designed for legacy COGO methodology users.
Type commands at the bottom prompt -> Press Enter -> Receive visual history feedback above.
Floating tips will guide you on expected parameter formats.

2.4 Cogo Script Tab (Batch Processing)
--------------------------------------------------------------------------------
Provides a multi-line text interface to paste large files.
Key actions:
- Run: Executes all lines blindly.
- Walk: Pauses execution between each line, opening a small 'next' prompt for QA.
- AI: Sends the script to GEMINI/GPT for logical analysis and correction.

2.5 Curve Solver Tab
--------------------------------------------------------------------------------
When you only have a sub-set of curve data. Enter EXACTLY two parameters (e.g., Radius 
and Arc Length). Clicking 'Solve' utilizes native math to produce remaining parameters 
like Chord, Tangent, and Delta. 

2.6 Piping Tab
--------------------------------------------------------------------------------
Form-driven pipe entry:
- Pipe Runs: Define start and end nodes, assign diameters and inverts, let slope auto-calc.
- Structures: Assign code logic (e.g., 'MH') to structural points.

2.7 Piping Script Tab
--------------------------------------------------------------------------------
For those who prefer to write out pipe networks rather than click UI forms.
Utilizes the PRUN/SS command structure.

2.8 Codes Tab
--------------------------------------------------------------------------------
The database of standard survey abbreviations. Controls the auto-formatting, symbol 
attachment, and validation rules logic across the application.

2.9 Figures Window
--------------------------------------------------------------------------------
A secondary window accessed via the Menu. It splits the screen into:
- Left: A DataGrid listing bounded shapes (Parcels, Easements).
- Right: A 2D Viewer rendering the geometry logic on a Cartesian plane.

2.10 Material Selection Window
--------------------------------------------------------------------------------
A graphical picker for specifying exactly what brand, material, and standard of pipe, 
valve, or fitting is being selected for the Bill of Materials.

vector graphic for CAD generation (e.g., UtilityPoleBlock).

PART 4: CORE SURVEY COMMANDS (COGO)
================================================================================
The parsing engine expects delimited text, classically spaced.

4.1 Setup & Orientation Commands
--------------------------------------------------------------------------------
** ST (Store Point)
Syntax: ST [PointId] [Northing] [Easting] [Elevation] [Description]
Action: Explicitly hardcodes a coordinate into the database.
Example: ST 100 5000 5000 100 TBM

** OC (Occupy Point)
Syntax: OC [PointId] [InstrumentHeight]
Action: Tells the active processing state that the total station is sitting at PointId.
Example: OC 100 5.25

** STN (Station Occupancy)
Note: Technically inter-changeable with OC in the legacy routine parser.
Action: Alias for OC.

** BS (Backsight)
Syntax: BS [PointId] [Azimuth_or_Bearing]
Action: Locks the orientation ring of the setup based on an azimuth pointing at a known.
Example: BS 101 45.0000

** FACE
Syntax: FACE [1 or 2]
Action: Specifies whether upcoming observations are Face 1 (direct) or Face 2 (reverse).

4.2 Creation & Geometry Commands
--------------------------------------------------------------------------------
** FS (Foresight)
Syntax: FS [NewPtId] [Angle] [Distance] [TargetHeight] [Description]
Action: Creates a singular point branching off the occupied setup.
Requires: Prior OC and BS command.
Example: FS 102 90.0000 100.00 0 EP

** TRAV (Traverse)
Syntax: TRAV [NewPtId] [Angle] [Distance] [TargetHeight] [Description]
Action: Creates a point just like FS, but immediately updates the Occupy (OC) state to sit
on the newly created point, setting the previous OC point as the new default BS point.

** AZ (Azimuth)
Syntax: AZ [Pt1] [Pt2]
Action: Calculates the mathematical azimuth and bearing from one coordinate to another.

** IN (Inverse)
Syntax: IN [Pt1] [Pt2]
Action: Fully inverses Pt1 to Pt2, providing Delta N, Delta E, distance, and bearing.

** LOC (Locate / Intersect)
Syntax: LOC [Type] [Pt1] [Ang/Dist] [Pt2] [Ang/Dist] [NewPt]
Action: A complex intersection command solving bearing-bearing, bearing-distance, 
or distance-distance intersections based on the Type flag.

** NEWPT (Next Available Point Number)
Syntax: NEWPT [Optional Seed String]
Action: Queries the database and returns the next unused integer Point ID string.

** ADDPT
Action: Appends point list references. Often wrapped internally by the system.

4.3 Transformation Commands
--------------------------------------------------------------------------------
** TRN (Translate)
Syntax: TRN [Point Range] [Delta N] [Delta E] [Delta Z]
Action: Bulk moves an array of points by massive coordinate shifts.
Example: TRN 100-200 50.0 50.0 0

** ROT (Rotate)
Syntax: ROT [Point Range] [BasePt] [Angle]
Action: Swings an array of points around a BasePt origin by the provided angle.
Example: ROT 100-200 100 45.0000

** LN (Line Transform - Best Fit)
Syntax: LN [FilePt1] [FilePt2] [LocalPt1] [LocalPt2] [Point Range]
Action: Implements an affine Helmert transformation translating and scaling points to 
sit upon a localized known baseline.

4.4 Information & Display Commands
--------------------------------------------------------------------------------
** ID (Identify)
Syntax: ID [PointId]
Action: Outputs the NEZ data of a single coordinate to the console UI.

** SQ (Sequence/Inquiry)
Syntax: SQ [StartId] [EndId]
Action: Same as ID, just spans a bulk range of IDs.

** DISP (Display)
Syntax: DISP [PointId]
Action: Similar to ID, commonly triggers graphical highlighting.

** LIST
Syntax: LIST [Type]
Action: Shows current memory contents (e.g., LIST SETUP).

** SHOW
Syntax: SHOW [Var]
Action: Equivalent to LIST but applies globally to variables.

** OUTPUT
Syntax: OUTPUT [Format]
Action: Alters logging styles (e.g. OUTPUT XML).

4.5 Measurement & Intersections
--------------------------------------------------------------------------------
** RKRK (Right Curve / Right Curve Intersection)
Syntax: RKRK [Arc1_CentroId] [Rad1] [Arc2_CentroId] [Rad2] [NewPt1] [NewPt2]
Action: Computes the 0, 1, or 2 geometric points where two perfect radius circles intersect.

** LNOFF (Line Offset)
Syntax: LNOFF [StartPt] [EndPt] [Offset] [Distance_Down_Line] [NewPt]
Action: Travels down a baseline and shoots left/right orthogonally to create a new point.

** RKOFF (Arc Offset)
Syntax: RKOFF [CenterPt] [RadiusNode] [Offset] [Delta_Sweep] [NewPt]
Action: Offsets tangentially off a radial track.

4.6 Alignment Commands
--------------------------------------------------------------------------------
** DEFHALN (Define Horizontal Alignment)
Syntax: DEFHALN [Name] [Start_Station] [PI_Pt1] [PI_Pt2] ...
Action: Builds a complex alignment string logic combining tangents and curves automatically.

** DEFVALN (Define Vertical Alignment)
Syntax: DEFVALN [Name] [PVI_Station] [PVI_Elev] [Curve_Length_Vertical] ...
Action: Used inherently for road design profiles.

4.7 Curve Commands
--------------------------------------------------------------------------------
Used extensively for plotting subdivisions.
** PC (Point of Curvature)
** PI (Point of Intersection)
** PT (Point of Tangency)
** CC (Curve Centerpoint)
** RT (Right Turn Arc)
** LT (Left Turn Arc)
** XD (Extend Distance)
** XC (Extend Curve Options)
These specify specific geometric dependencies for laying out non-linear segments. For example,
an XC command explicitly provides parameters when dealing with spiral transition curves.

4.8 Database Maintenance Commands
--------------------------------------------------------------------------------
** DELPT (Delete Point)
Syntax: DELPT [PointID | StartPt-EndPt]
Action: Wipes a single point or a continuous range of points from RAM and SQLite completely.

** EDTPT (Edit Point)
Syntax: EDTPT [PointID] [Optional N] [Optional E] [Optional Z]
Action: Overwrites existing memory references natively.

** COPY-PT or COPYPT (Copy Point)
Syntax: COPY-PT [SrcID] [DestID] [Description]
Action: Clones geometry under a different index key. Optionally takes a new description.

PART 5: FIGURES AND BOUNDARIES
================================================================================

5.1 Figure Generation
--------------------------------------------------------------------------------
Figures are created via three primary string designations during a bulk script batch.
- ** B (Begin): Opens a new graphical sequence array.
  Syntax: B [FigureName] [StartPtID]
- ** L (Line): Extends the current active figure bounding box to the target ID.
  Syntax: L [NextPtID]
- ** C (Close): Commands the system to draw a final geometry line from the last active 
  point back to the opening Base Point specified in B, and designates IsClosed=True.

5.2 DXF Export Logic
--------------------------------------------------------------------------------
Only data grouped by Figures or Validated Piping paths get exported cleanly to DXF vector 
output. Scattered, unconnected points normally export as basic text nodes rather than polylines.

5.3 Reviewing Figures
--------------------------------------------------------------------------------
Open the 'Edit Figures' window from the main menu. Here, you should delete erroneously 
generated shapes and re-sync natively to the Installed Assets payload.

PART 6: PIPING NETWORK MODELLING
================================================================================

6.1 Piping Fundamentals
--------------------------------------------------------------------------------
In RCS COGO Enterprise, underground utilities are not just strings, but physical volumetric
models mapping specific 3-dimensional data points (inverts, slopes, disciplines).

6.2 UI-Based Piping Workflows
--------------------------------------------------------------------------------
Use the dedicated Pipeline Tab:
1. Input Upstream Node ID
2. Input Downstream Node ID
3. Set inverts (must be numerically matched or lower than surface topology elevation).
4. Run 'Validate Network'.

6.3 Scripting Pipes
--------------------------------------------------------------------------------
In the Piping Script window:
Use 'PRUN START' to commence modeling a multi-segment transmission main. 
Use 'SS-B' combined with a PointID to spawn an automated structural vault/manhole at the 
run's genesis based on validation sizing rules.

6.4 Network Validation & Error Checking
--------------------------------------------------------------------------------
Validation explicitly flags issues such as:
- Negative diameter values
- Defying gravity (End Invert > Start Invert for Gravity/WW lines)
- Missing coordinate origins

6.5 Synchronizing to Installed Assets DB
--------------------------------------------------------------------------------
The critical handshake linking raw memory design to the master project SQLite.
Pressing this checks global schema compatibility for fields such as Layer, DescriptionID,
and Discipline_Ref.

PART 8: EXPORTING AND REPORTING
================================================================================

8.1 Points XML and TXT
--------------------------------------------------------------------------------
Raw dumps of the Points table. TXT relies on configurable fixed widths (e.g. Pt,N,E,Z,D)
whereas XML natively formats nodes for Trimble or Leica data controller ingestion.

8.2 Script Outputs
--------------------------------------------------------------------------------
Generates audit logs showing precisely which lines executed, the timestamp, and the 
calculated geometric result array in JSON block form for archival tracing.

8.3 DXF Output
--------------------------------------------------------------------------------
AutoCAD natively digestible R14 compliant text schemas. Will produce Polyline entities 
for all explicitly 'closed' Figures. 

8.4 ePANET Imports
--------------------------------------------------------------------------------
An upcoming module converting Gravity/WW nodes to compatible INP string files, 
extracting native coordinate arrays directly.

8.5 CSV BOM Generation
--------------------------------------------------------------------------------
Bill of Materials format generating spreadsheet columns: ItemCode, Description, Unit, Qty.

PART 9: TESTING PROTOCOLS & QA/QC
================================================================================

9.1 Unit Testing Guidelines
--------------------------------------------------------------------------------
Prioritize testing memory retention. The fundamental issue discovered during initial QA 
was EF Core tracking exceptions holding on to ghost vertices during Figure manipulation.
The 'Raw Sql deletion' update mitigates this; tests should stress-test immediate sync-back.

9.2 Walkthrough 1: Barebones Points Setup
--------------------------------------------------------------------------------
1. Main Shell -> Points Tab.
2. Use Cogo window -> ST 100 5000 5000 100 START
3. Use Cogo window -> ST 200 5000 6000 100 END
4. Verify points tab generated two lines immediately.
5. Hit 'Save Points' ensuring the AppDbContext triggers .SaveChanges().

9.3 Walkthrough 2: Advanced Batch Scripting
--------------------------------------------------------------------------------
1. Navigate to Cogo Script view.
2. Write:
   ST 1 1000 1000 100
   OC 1 5.0
   BS 2 0.0
   FS 2 90 200 0.0 POINT2
   FS 3 180 200 0.0 POINT3
   FS 4 270 200 0.0 POINT4
   B SQUARE 1
   L 2
   L 3
   L 4
   C
3. Run Script. Ensure 'SQUARE' generates visually in the Figures Window cleanly.

9.4 Walkthrough 3: Pipe Network Integration
--------------------------------------------------------------------------------
1. Take nodes 1, 2, 3, 4 from above.
2. Pipe Script -> 'PRUN START 1 2 8 90 85'
3. Sync. Verify in the materials logic that an 8-inch pipe spanning 200ft is logged.

9.5 Walkthrough 4: Alignment Validation
--------------------------------------------------------------------------------
1. Test curve solutions via the Curve Solver.
2. Ensure mathematical output Delta values strictly format as DMS strings (DD.MMSS).

PART 10: TROUBLESHOOTING & FAQ
================================================================================

10.1 UI Freezes and Database Locks
--------------------------------------------------------------------------------
Symptom: Program freezes on Sync To Assets.
Cause: SQLite exclusively locked the DB because a DataGrid cell remained in Edit Mode.
Fix: Ensure you click out of the cell so RowEditEnding explicitly invokes and detaches
EF modifications prior to DB interactions.

10.2 EF Core Concurrency Exceptions
--------------------------------------------------------------------------------
Symptom: Crashing entirely upon clicking Delete Figure.
Cause: Overlapped hierarchy tracing where Vertices didn't cascade delete on tracked entities.
Fix: Solved in Version 2.1 via direct ExecuteSqlRaw string injections manually flushing arrays.

10.3 Error Log Locations
--------------------------------------------------------------------------------
If an Unhandled Exception terminates the WPF sequence, trace the .NET dump file located in
%AppData%/RCS_Crash_Dumps. 

10.4 Glossary of Terms
--------------------------------------------------------------------------------
- Invert: The bottom most elevation point of an internal pipe circumference.
- Azimuth: The bearing measured clockwise strictly from North.
- Backsight: The directional geometric baseline allowing triangulation.
- Figure: An array sequence of Points forming a visible 2D shape or boundary.
- Asset: A distinct modeled unit represented physically in real-world construction limits.

--- EXTENDED COMMAND REFERENCE SUB-BLOCK #1 ---
* Note regarding ST command: Ensure numeric variables strictly follow standard US parsing schema.
  Decimals should be formatted as X.XX. 
* Note regarding OC command: When no Target Height is given, default assumed is 0.00.
* Note regarding DXF Export Command Matrix:
  Depending on map coordinate shifts, always apply transformations (TRN) in the Cogo Tab *PRIOR*
  to generating DXF outputs to prevent unscaled projection distortion.
  When testing the LNOFF (Line Offset) logic, remember the directionality matters. Looking down
  the line from StartPt to EndPt, a positive offset pushes right, negative offset pushes left.
  Always evaluate boundaries by checking the Closure Output log after a B / L / C figure statement.
  If mapcheck falls outside General Settings tolerance, the parcel is flagged as Erroneous.

  [INTERNAL SYSTEM CHECKLIST 001]
  - Validated Pipe Types: PVC, DIP, HDPE
  - Standard Gravity Classes: SDR35, SDR26
  - Standard Pressure Classes: C900, DR18, DR14

  [COGO COMMAND: AZ (Azimuth/Bearing) EXTENDED]
  Allows quick derivation of geometric path relations.
  Format options include NEZ, XY, ENZ configurations subject to the project settings.
  
  [COGO COMMAND: FS (Foresight) EXTENDED]
  Under standard topographic workflows, the FS command is your primary data-entry vector.
  Remember that angle syntax must adhere to the DD.MMSS or DDD.MMSS convention for
  strict interpretation by the angle parser. Eg: 180 degrees 30 minutes 45 seconds is 180.3045.
  
  [COGO COMMAND: TRAV (Traverse) EXTENDED]
  TRAV acts as a compound wrapper around an FS followed by an OC. Use carefully inside scripts 
  as mis-identifying the sequential chain will throw the coordinate tracking entirely out of bounds.

  [SUPPORT CONTACT]
  Reach out to RCS Enterprise Technical Deployment team for custom native C++ security DLL
  integrations or specialized hardware verification.

  [PIPING HIERARCHY RULES]
  1. Points must exist before Pipe Runs.
  2. Pipe Runs must be explicitly declared before Structures bind to endpoints.
  3. Master validation algorithm recursively crawls the network tree starting from lowest
     invert elevation checking contiguous gravity flow.

  [DEBUGGING NOTES]
  Memory leaks in FiguresDataGrid resolved by explicitly nulling ItemsSource and coercing
  the filtered array locally. ToList() evaluation executes LINQ properly without DB delay.
  Always ensure ComboBox elements in WPF avoid raw generic Styles without BorderThickness
  management to suppress Windows OS theming overrides.
  
  (End of Reference Sub-Block)

PART 11: RECENT MODERNIZATION FEATURES (VERSION 2.0+)
================================================================================

11.1 Project Metadata (Project Details Window)
--------------------------------------------------------------------------------
Access via 'Project > Details...' from the Main Menu.
This dialog captures granular engineering metadata (e.g., Engineer of Record, EOR Sign Date, 
Project Name, Date Started, Date Finished). This metadata is universally applied to the active
project and persists in the SQLite database to facilitate formal JEA AS-BUILT reporting outputs.

11.2 Tables & DXF Export
--------------------------------------------------------------------------------
Access via the 'Tables' menu located in the Main Shell.
This feature presents a multi-tab preview window that automatically parses installed 
assets from the active Project ID. 
- Included Tables: Force Main Fittings, Sanitary Manholes, Water Main Fittings, Water Valves, 
  Hydrants, Water Services, and Locate Wire Boxes.
- Export to DXF: The primary action button "📐 Export Tab → DXF" constructs an AutoCAD-ready 
  table (drawing actual LINE and TEXT entities in ACI magenta/cyan/white format) 
  compliant with the JEA As-Built field table template.

11.3 Points Along Pipe (PAP)
--------------------------------------------------------------------------------
Access via the Main Shell (or piping menus if configured).
The 'Points Along Pipe' engine automatically extracts pipeline vertices and inserts 
calculated 3D nodes (specifically, inverts) at designated intervals (e.g., 50 FT).
- Use Case: Rapidly generating topographic tracking points for pressure mains and gravity 
  sewers, drastically reducing manual COGO computation time during long transmission design.
- The interpolated nodes map dynamically to your selected coordinate system (e.g., State Plane).

11.4 Application Output
--------------------------------------------------------------------------------
Distribution uses Inno Setup (Installer.iss) to neatly package the WPF binaries,
required native SQLite providers, and .json configuration templates into a single setup 
wizard for end-users, shielding them from environment complexity.
